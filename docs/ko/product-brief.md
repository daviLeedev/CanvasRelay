## 제품 요약

CanvasRelay는 로컬과 클라우드 공급자를 오가며 이미지와 영상을 생성,
편집, 추적, 재사용하는 로컬 우선 AI 미디어 오케스트레이션 스튜디오다.

이 제품은 모델별 입력 폼을 모아놓은 갤러리가 아니다. 서로 다른 생성
엔진을 하나의 관찰 가능한 작업 생명주기로 정규화하고, 레퍼런스,
프롬프트, 진행 상태, 결과, 생성 이력, 재사용을 일관된 작업 공간에서
다룬다.

## 문제

AI 미디어 작업은 공급자 웹사이트, 로컬 추론 서버, 모델별 제어 화면,
임시 다운로드 폴더, 일회성 스크립트에 분산되어 있다. 이로 인해 다음
문제가 반복된다.

- 공급자마다 요청 방식과 작업 상태 모델이 다르다.
- 오래 걸리는 작업을 관찰하고 취소, 재시도, 비교하기 어렵다.
- 프롬프트, 모델, 레퍼런스, 파라미터의 생성 이력이 쉽게 사라진다.
- 결과물이 재사용 가능한 제작 자산이 아니라 서로 단절된 파일이 된다.
- 로컬 도구가 하나의 작업 흐름 대신 내부 구현 세부사항을 노출한다.

## 제품 포지셔닝

> 다양한 AI 미디어 엔진으로 창작 의도를 전달하면서 작업 가시성과 자산
> 생성 이력을 잃지 않게 해주는 제작 콘솔.

CanvasRelay는 단순한 모델 연동 이상을 보여줘야 한다. 비동기 작업, 타입이
있는 계약, 실패 복구, 미디어 생명주기, 점진적 향상을 중심으로 프론트엔드와
백엔드가 협력하는 방식을 보여주는 제품이다.

## 대상 사용자

### 주요 사용자

- 여러 로컬 이미지 또는 영상 모델을 하나의 안정적인 스튜디오에서
  사용하려는 크리에이터.
- 공급자, 프리셋, 레퍼런스를 비교하는 테크니컬 아티스트.
- 오래 걸리는 AI 작업을 제품에 통합하는 방식을 평가하는 개발자.

### 포트폴리오 리뷰어

선임 개발자도 의도된 사용자다. 저장소는 검토 시간에 따라 다음 질문에
답할 수 있어야 한다.

| 검토 시간 | 저장소가 답해야 하는 질문 |
| --- | --- |
| 30초 | 어떤 문제를 해결하며, 화면은 어떻게 생겼는가? |
| 5분 | 인증정보나 GPU 없이 의미 있는 흐름을 실행할 수 있는가? |
| 20분 | UI, 도메인, 공급자, 저장소의 책임이 분리되어 있는가? |
| 60분 | 트레이드오프, 테스트, 실패 처리, 마이그레이션 결정이 설득력 있는가? |

## 사용자가 해결하려는 일

1. 프롬프트와 선택적 레퍼런스가 있을 때 공급자마다 다른 화면을 배우지
   않고 이미지나 영상을 만들고 싶다.
2. 생성에 몇 분이 걸릴 때 대기, 실행, 정지, 완료, 실패 상태를 정확히
   알고 싶다.
3. 유용한 결과가 나왔을 때 정확한 생성 방법을 확인하고 다른 작업의
   입력으로 재사용하고 싶다.
4. 공급자가 사용할 수 없을 때 입력을 잃거나 스튜디오 전체가 불안정해지지
   않으면서 다음 행동을 안내받고 싶다.
5. 프로젝트를 평가할 때 유료 인증정보, 독점 모델, 고성능 GPU가 없어도
   결정적인 데모를 실행하고 싶다.

## 핵심 제품 영역

### 이미지 작업 공간

- Text-to-image와 image-to-image 작업.
- 프롬프트, 네거티브 프롬프트, 레퍼런스, 공급자, 프리셋, 고급 설정.
- 크롭하지 않는 큰 결과 스테이지와 비교 및 재사용 액션.
- Mock 공급자와 선택적인 ComfyUI 공급자 지원.

### 영상 작업 공간

- 길이, 프레임, 모션, 품질 설정을 가진 image-to-video 작업.
- 대기, 실행, 인코딩, 완료 상태의 명확한 구분.
- 영상 미리보기, 메타데이터, 재시도, 재사용 액션.

### 작업 센터

- 대기, 실행, 완료, 실패, 취소 상태의 통합 표현.
- 공급자가 제공할 때 실제 이벤트에 근거한 진행률.
- 대기 작업 취소와 실행 작업의 최선 노력 중단.
- 원본 요청의 변경 불가능한 스냅샷을 이용한 재시도.

### 미디어 라이브러리

- 이미지와 영상 필터, 반응형 밀도, 상세 보기.
- 프롬프트, 레퍼런스, 공급자, 모델, 파라미터, 시각, 파일 출처.
- 이미지 입력, 영상 입력, 새 편집 요청으로 재사용.
- 실용적인 2D 그리드와 선택적 공간 비교 모드.

### 프롬프트 코파일럿

- 현재 창작 의도에서 새로운 프롬프트와 네거티브 프롬프트를 생성한다.
- 공급자 어댑터를 사용하며 브라우저에 인증정보를 노출하지 않는다.
- 생성의 숨겨진 필수 의존성이 아니라 작업을 돕는 기능이다.

### 시스템 상태

- API, 공급자, 저장소, 선택적 추론 서버의 준비 상태.
- 가려진 인증 상태와 사용자가 행동할 수 있는 최근 오류.
- UI 응답에 원본 토큰, 비밀정보, 개인 파일 경로를 포함하지 않는다.

## 이머시브 3D 경험

3D 계층은 화면을 꾸미는 것이 아니라 제품 상태를 전달해야 한다.

- 생성 스테이지는 레퍼런스, 현재 처리, 결과를 상호작용 가능한 미디어
  플레인으로 투영할 수 있다.
- 파이프라인 보기는 Prompt -> Provider -> Job -> Asset 전환을 표현한다.
- 공간 비교는 여러 결과물을 선택하고 검사하기 좋게 배치한다.
- 폼, 메타데이터, 로그, 삭제 액션은 접근 가능한 DOM UI로 유지한다.
- 지원하지 않거나 성능이 제한된 장치에서도 완전한 2D 대체 화면을 제공한다.

첫 화면은 마케팅 랜딩 페이지가 아니라 실제 사용 가능한 스튜디오다.

## 제품 원칙

1. **화려함보다 운영 명확성.** 움직임과 깊이는 상태를 설명해야 한다.
2. **점진적 공개.** 자주 쓰는 설정은 바로 보이고, 공급자별 파라미터는
   작업을 방해하지 않는 위치에서 사용할 수 있어야 한다.
3. **로컬 우선과 공급자 중립성.** Mock 모드로 실행할 수 있고 명시적
   어댑터를 통해 로컬 또는 클라우드 공급자를 연결한다.
4. **기본 제공되는 생성 이력.** 모든 자산은 자신을 만든 요청을 설명한다.
5. **실패도 핵심 상태.** 입력은 복구 가능하며 오류는 다음 행동을 안내한다.
6. **접근 가능한 핵심 흐름.** 3D, 모션, 고급 하드웨어는 선택 사항이다.
7. **정직한 기능 표시.** 공개 프로젝트는 구현하고 검증한 공급자 연동만
   표시한다.

## 공개 포트폴리오 범위

### 포함 범위

- Next.js와 TypeScript 웹 애플리케이션.
- FastAPI 오케스트레이션 API.
- 결정적 결과를 내는 1급 Mock 공급자.
- 문서화된 설정을 가진 선택적 ComfyUI 어댑터.
- 이미지 생성, 이미지 편집, image-to-video, 작업 센터, 라이브러리.
- 기능적인 3D 생성 스테이지와 공간 비교.
- 타입이 있는 API 계약, 테스트, CI, 아키텍처 문서.

### 첫 공개 릴리스에서 제외하는 범위

- 모든 비공개 워크플로와 모델 프리셋 이전.
- 모델 가중치, 비공개 생성 미디어, 공급자 인증정보 배포.
- 릴리스 전에 기존 화면의 모든 설정을 재현하는 작업.
- 범용 노드 편집기 제작 또는 ComfyUI 대체.
- 문서화된 API로 검증할 수 없는 공급자 지원 주장.
- 3D 장면을 필수 작업 흐름으로 만드는 것.

## 데모 전략

`DEMO_MODE=true`는 스크린샷용 가짜 화면이 아니라 지원되는 제품 모드다.

- 결정적인 대기, 실행, 완료 작업을 생성한다.
- 복구 흐름 시연을 위해 타입이 있는 실패를 의도적으로 만들 수 있다.
- 검토된 안전한 예시 자산과 메타데이터를 제공한다.
- 취소, 재시도, 필터, 상세 보기, 재사용 흐름을 지원한다.
- 계정, 비밀정보, 모델 파일, GPU가 필요하지 않다.

## 성공 지표

### 사용자 경험

- 처음 사용하는 사람이 설명 없이 Mock 결과를 생성하고 찾을 수 있다.
- 작업 상태는 항상 대기와 실행, 알 수 없는 진행 상태를 구분한다.
- 마지막 제출 프롬프트와 선택 결과는 비파괴적 새로고침 후에도 유지된다.
- 데스크톱, 태블릿, 모바일에서 핵심 흐름을 사용할 수 있다.

### 엔지니어링 품질

- 웹 타입은 API 계약에서 생성되거나 계약과 일치하는지 검사한다.
- 공급자 응답 파싱 오류가 사용자에게 처리되지 않은 예외로 노출되지 않는다.
- 작업 전환, 취소, 재시도, 생성 이력을 핵심 도메인 테스트로 검증한다.
- 데모 모드에서 이미지와 영상 흐름을 각각 E2E 테스트한다.
- CI가 포맷, 린트, 타입 검사, 테스트, 빌드, 비밀정보 검사를 수행한다.

### 성능과 접근성

- 애플리케이션 셸과 핵심 설정은 3D 번들을 기다리지 않는다.
- 3D 렌더러는 숨김 또는 유휴 상태에서 멈추고 사용하지 않는 텍스처를
  해제한다.
- 모션 감소와 2D 대체 모드에서도 모든 필수 액션을 사용할 수 있다.
- WebGL 캔버스와 상호작용하지 않아도 키보드 포커스, 라벨, 상태 안내,
  오류 메시지가 동작한다.

## 릴리스 완료 정의

첫 포트폴리오 릴리스는 리뷰어가 저장소를 복제하고, 문서의 명령으로 데모
모드를 시작하고, 이미지 작업을 제출하고, 생명주기를 관찰하고, 결과와
생성 이력을 검사하고, 결과를 영상 요청에 재사용하고, 비공개 의존성 없이
자동 검사를 실행할 수 있을 때 완료된다.
