# ADR 0002: PostgreSQL 메타데이터와 파일시스템 미디어

| 항목 | 값 |
| --- | --- |
| 상태 | 승인 |
| 날짜 | 2026-08-01 |

## 배경

CanvasRelay의 작업과 라이브러리 결과는 API 또는 추론 Provider가 재시작해도
유지되어야 한다. 작업 목록에는 관계형 필터와 안정적인 커서 페이지네이션이
필요하지만, 원본 이미지와 영상에는 스트리밍, Range 요청, 향후 오브젝트
스토리지 전환이 중요하다. 대용량 바이너리를 데이터베이스에 직접 넣으면
백업과 캐시 비용만 커지고 미디어 전송에는 도움이 되지 않는다.

## 결정

- Docker와 배포 환경에서는 PostgreSQL을 메타데이터의 단일 진실 공급원으로 사용한다.
- SQLAlchemy 2.x와 psycopg 3을 사용하고 Alembic으로 스키마를 변경한다.
- 단위 테스트와 선택적인 단독 로컬 실행에는 같은 계약의 SQLite 구현을 유지한다.
- 실제 파일은 명시적인 `DATA_DIR` 아래에 저장한다. DB에는 상대 storage key,
  MIME, 해상도, 크기, SHA-256, 출처와 파일 상태만 저장한다.
- 완료 파일은 원자적으로 이동하고 라이브러리용 WebP 썸네일을 별도로 만든다.
- 기존 SQLite 데이터는 원본을 삭제하지 않는 멱등 CLI로 가져온다.

## 결과

PostgreSQL 실행과 마이그레이션 단계가 추가되지만 동시 접근, 인덱스, JSONB,
참조 무결성을 얻는다. 파일시스템 미디어는 로컬 포트폴리오에서 단순하고 빠르며,
나중에 Job 계약을 바꾸지 않고 오브젝트 스토리지 구현으로 교체할 수 있다.

DB와 파일 저장은 하나의 ACID 트랜잭션이 될 수 없다. 따라서 원자적 파일 교체,
체크섬, missing 메타데이터와 복구 가능한 정리 절차로 불일치를 숨기지 않고
관찰 가능하게 처리한다.
